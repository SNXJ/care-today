# 周期复诊汇总（不良反应 + 用药）设计

> 状态：已评审待实现 · 日期：2026-10-19

## 目标

照护者需要把一段时间内的**不良反应（症状）**和**用药**整理成一段文本，发给医生。
手动整理繁琐。本功能：选开始/结束日期 → 后端聚合该区间的症状与用药 → 生成可直接复制的汇总文本。

示例输出：

```
【不良反应 · 9/22–10/9】
腹泻 9/24
发烧38° 9/30
便血 9/22-9/23、9/29、10/8-10/9

【用药 · 9/22–10/9】
蒙脱石散 2包 9/24、9/29
美林 10ml 9/30
```

## 范围

- **后端**：新增聚合接口，格式化逻辑集中在此（单一真相，未来网页/小程序可复用）。
- **Flutter App**：在「全部记录」页加入口，调接口并把结果复制到剪贴板。
- 本期不改网页端、不改小程序端（接口已就位，以后接入成本低）。

## 数据来源（现有表，不新增表）

- `symptom_events`：`tag`(VARCHAR40)、`happened_at`、`note`。症状 = 完整 tag 字符串。
- `medication_logs`：`name`(VARCHAR80)、`dosage`(VARCHAR60)、`taken_at`、`note`。
- 两表均有 `space_id`、`deleted_at`。

## 后端设计

### 接口

```
GET /api/spaces/{spaceId}/summary?from=YYYY-MM-DD&to=YYYY-MM-DD
```

- 鉴权：与其它空间接口一致（需为该空间成员）。
- 参数校验：`from`、`to` 为合法日期且 `from <= to`；缺省时后端不填默认（默认值由客户端传），非法返回 400。
- 返回：
  ```json
  { "from": "2026-09-22", "to": "2026-10-09", "text": "……拼好的汇总文本……" }
  ```

### 查询

- 区间为**本地日期闭区间**，按服务器时区 `Asia/Shanghai` 解释：
  实际查询条件 `happened_at >= from 当日 00:00`（本地）且 `happened_at < (to+1) 当日 00:00`（本地），`deleted_at IS NULL`，限定 `space_id`。
- 症状、用药各查一次。

### 聚合与格式化（核心逻辑）

**分组**
- 症状：按**完整 `tag`** 分组（"发烧38°" 与 "发烧39°" 是两组）。
- 用药：按 **(`name`, `dosage`)** 分组（dosage 为空视作空串）。

**日期收集与区间合并（两类共用）**
1. 每组收集所有记录的**本地日期**（year-month-day），去重，升序。
2. 连续日期（相邻、差一天）合并为区间：`[9/22, 9/23]` → `9/22-9/23`；单天 → `9/24`。
3. 跨月照常：`9/30` 与 `10/1` 连续 → `9/30-10/1`。
4. 各区间/单天之间用 `、` 连接。
5. 日期格式 `M/D`（无年份、无前导零）。

**单行格式**
- 症状：`<tag> <日期串>` → `腹泻 9/24`
- 用药：`<name> <dosage> <日期串>`（dosage 为空则省略那一段）→ `蒙脱石散 2包 9/24、9/29`

**整体文本**
```
【不良反应 · <from M/D>–<to M/D>】
<症状行，按首次出现日期升序>

【用药 · <from M/D>–<to M/D>】
<用药行，按首次出现日期升序>
```
- 两段之间一个空行。
- 某段无记录：该段仅一行 `无`。
- `note`（备注）**不纳入**汇总。
- 不含患者姓名等任何抬头。

### 代码落点

- 新增 `SummaryService`（或并入 `CareService`）承载聚合+格式化；纯函数式的区间合并/格式化单独可测。
- `CareRepository` 新增按区间查询 symptom/medication 的方法（或复用现有 list 方法后在内存过滤——数据量小，二者皆可；优先 SQL 带区间）。
- `CareController` 新增 `@GetMapping("/spaces/{spaceId}/summary")`。

## Flutter 设计

- 「全部记录」页顶部加按钮 **「生成复诊汇总」**。
- 点击 → `showDateRangePicker`，默认区间 = **最近 21 天**（`今天-20 天 .. 今天`，闭区间共 21 天），可改。
- 选定后调 `GET /spaces/{id}/summary?from=..&to=..`。
- 结果弹窗：可滚动展示 `text`（复用已可滚动的弹窗形态），**打开即自动 `Clipboard.setData`**，toast 提示「已复制，可粘贴发给医生」；弹窗内另留一个「复制」按钮便于再次复制。
- 失败（网络/400）走现有 `showError`。

## 边界与异常

- 区间内两类都无记录 → 两段都是 `无`。
- 同一症状/用药同一天多条 → 该天只出现一次。
- `from > to` 或非法日期 → 400（`ApiExceptionHandler` 已统一成友好提示）。
- 超长文本 → 弹窗可滚动（已修的 `showManageSheet` 同理），不截断。

## 测试

- **后端单测**（纯函数优先）：
  - 区间合并：连续、跨月、单天、多段混合（对应示例 `便血` 那行）。
  - 分组：相同 tag 合并、不同 tag（含数值差异）分开；用药按名称+剂量分组。
  - 空段落 → `无`。
  - 日期格式 `M/D` 无前导零。
- **接口测试**：`from>to` → 400；正常区间 → 200 且 text 符合预期。

## 不做（YAGNI）

- 不做网页/小程序入口（本期）。
- 不做 PDF/图片导出、不做历史汇总留存、不做自定义模板。
- 不解析症状里的数值（体温等）——按完整 tag 原样处理。
